# Tool catalog

Tools are executable operations selected and taught by capability documents. They live
in the repo's `ronin_bin/`,
which `setup.sh` puts on PATH — call them by bare name, never by a built path.
(`shim/tmux` is the exception below: it is PATH interception, not a command you type.)
Agents: prefer the selected tool over hand-rolled choreography; it reports the result in
the vocabulary used throughout the coworkspace.

| Tool | Operation | Usage |
|---|---|---|
| `shim/tmux` | — | On PATH ahead of real tmux: makes `kill-server` unavailable because it ends every session. All other tmux commands pass through. |
| `ronin-url` | — | Prints where the live operator answers, one line: `RONIN_URL` when set (a development/test target over HTTP), else the path of the operator's own Unix socket — `RONIN_SOCKET` as told at birth, else `<data root>/run/ronin.sock`. The socket is the address, the liveness check and the credential; no tmux is consulted (`docs/operator-connection.md`). Exit 4 with one of two refusals: no Ronin has started here (no socket), or Ronin is not running (socket, nobody listening). Shell callers build their request through the sourced sibling `ronin-http.sh` (`ronin_connect` sets `url` and `RONIN_CURL`), and resolve both beside their own real file, so an absolute path or projected symlink never depends on Ronin directories being on `PATH`. |
| `ronin-host` | survey-machine, survey-account, survey-secrets, restart-ronin | `ronin-host --help` renders the available fixed subcommands. `inspect [path]` measures host and storage; `account` reports secret-free ownership and entitlement; `secrets [path]` reports key names and exposure, never values; `restart` restarts Ronin and nothing else without touching sessions. There is no generic writer or arbitrary service target. |
| `ronin-repo-init` | repository-initialize | `ronin-repo-init <existing-project-root>` → `INITIALIZED <path> — local repository only; no remote was assumed`, or `READY` when one already exists. It runs local `git init` only; it never creates the root or adds a remote. Exit 2 = bad argument. |
| `tejun-send` | send-to-session | Use `tejun-send <session> <message...>` for one session, with no board in between. It returns `DELIVERED` when it entered immediately, or `QUEUED … (message <id>)` when it cannot. Both are accepted outcomes: the durable Messages flow keeps checking safe delivery and exposes Try Again / owner-only Force. |
| `session_end` | harakiri | `session_end` — **no arguments**. Resolves the current Agent, preflights all assigned desks, automatically closes every clean desk whose tip is contained in its Team line (an ACCEPTED hand-in is enough; global-dev promotion and manual close are not required), then ends the Agent. Any dirty, pending/rejected, unique, shared, or occupied desk keeps the whole operation live and prints exact next actions; nothing is discarded. No output on success. Exit 4 = actionable refusal or owner-dialled; exit 5 = Ronin unreachable/stuck. |
| `session_archive` | archive-session | `session_archive <session>` → `ARCHIVED <session> as <archive-id> — resumable`. Uses the existing live-session archive route; it never substitutes hard delete. Exit 2 = bad arguments, 4 = refused, 5 = unreachable. |
| `session_restore` | rehydrate-session | `session_restore <archive-id>` → `REHYDRATED <session>`. Uses the existing provider-resume and metadata-restoration route; the manifest is removed only after restoration succeeds. Exit 2 = bad arguments, 4 = refused, 5 = unreachable. |
| `tejun-team` | team-roster | `tejun-team <team>` → the sessions on that team, one per line + dial. No arg → every team in play, with counts. Exit 3 = no such team. Reads tmux directly, so it answers even when Ronin isn't running. |
| `session_fork` | session-launch | **Launch one visible Ronin Agent by required `--name`.** An optional quoted instruction, `--team`, repeatable `--behaviour ways:<book>`, `--provider`, `--model`, or `--dial user|read|write` state only what was chosen. Omission inherits the caller's Campaign and first Team, then the Campaign and install launch defaults; blank Control falls back to read-and-write. It returns one `BORN` or `REFUSED` result and never types into a pane. |
| `session_check` | agent-check | **Read one live session by exact name.** An unused name reports `NO-SESSION`; this tool never creates or changes anything. |
| `session_create` | agent-create | **Explicitly create one Agent through the ordinary launch resolver.** `session_create --help` reads and renders the current provider/model choices, recorded availability, and applicable Campaign defaults from the same canonical sources as the UI dropdowns; the executable keeps no model inventory. `--provider <provider> --model <model>` selects and forwards one current catalog pair unchanged. An existing name is refused rather than read or updated. Use `session_fork` for the no-fuss context-inheriting launch. |
| `session_set` | agent-update | **Change named facts on one existing live session.** It updates Team membership, lead designation, or project root; a missing name is refused and the bare form points to `session_check`. |
| `tejun-team-set` | team-upsert | **Make a team, or change its facts — the rare door.** `tejun-team-set <team> [--objective <text>] [--root <project_root>] [--repos a,b] [--branch <b>] [--campaign-defaults] [--add s1,s2]` → `CREATED <team>` or `UPDATED <team>`. Creation inherits the current Campaign's Team defaults, with named values final; update omission preserves the Team. `--campaign-defaults` is the explicit one-time repair for an existing Team. `--add` tags live sessions onto it (additive; a name not live is reported, the rest go through). Exit 2 = bad arguments, 4 = refused, 5 = unreachable. |
| `tejun-wipeboard` | wipeboard-check, wipeboard-post | Use the wipeboard for team-wide messages: rules, collisions, line state, and anything everyone must see. **Two bare forms are the whole ability.** `tejun-wipeboard` prints unread posts; `tejun-wipeboard post [--to a,b|all|none] <text>` posts to the current Team. A bare post interrupts the lead, addressing changes interruptions, and every member can read the post. On several Teams the tool reports the choice and uses the first Team. Unknown leading flags are reported and included as text. A named board supports `read`, `find`, and `boards`. |
| `tejun-jikan` | schedule-request | Bare `tejun-jikan` lists the current Team's Cron jobs. Add the same fields as the form: Request, To, When, Expires, and one-off or recurring. Example: `tejun-jikan add --to lead --when "weekdays 09:00" --kind recurring --expires "2026-12-31 17:00" --team studio "Review the overnight results"`. `pause`, `resume`, `now`, and `remove` change one. |
| `tejun-teampage` | team-page-read, team-page-draft | Bare `tejun-teampage` prints the Team page. `tejun-teampage <key=value …>` applies a draft while omitted values stay unchanged. `--team <t>` selects a Team; otherwise an ambiguous choice is reported and the first Team is used. Control remains visible and does not restrict arrangements. |
| `mika` | ask-house-assistant | `mika "<request>"` → hands plain words to the house assistant, starting her if needed. Her selected tools constrain what she can read or propose; the launcher carries no job vocabulary. When she is already up it hands off to `tejun-send`, so the request is either `DELIVERED` or durably `QUEUED`; starting her prints `STARTED`, and exit 5 = Ronin unreachable. |
| `lookup` | report-outcome | **Mika only.** `lookup mika-source:<id>` → prints one source from the index she was born with, verified against it. Exit 2 = not one exact reference; 4 = no operator socket. |
| `owner_view` | report-outcome | **Mika only.** `owner_view <tab>` → what the owner is looking at in that browser tab: workbench, team, selected workspace, what each visible workspace shows. Absent or stale view = 404, so open Help in the tab you mean. |
| `show` | report-outcome | **Mika only.** `show <tab> <surface>` → opens a Ronin surface in another visible workspace of that tab; never replaces the selected one. |
| `tejun-peek` | session-catchup | `tejun-peek <session> [lines=60]` → recent pane output, ANSI-stripped. |
| `tejun-rireki` | session-catchup | `tejun-rireki <session> since` → everything the pane emitted since the owner's last message; `… text [KB]` → the tail as readable text; `… <session>` → what the tape holds (segments, marks, dial); no arg → every tape in play. Reads the tape file, so it answers for sessions with no tile open, and when Ronin isn't running. The strip is dumb by design — repaints are left in; Ronin's lens is the one that collapses them and labels the result as reconstruction. |
| `read_tegami` | read-letter | `read_tegami` → your letter; `--json` → just the block; `--rungs` → the positions a marker can point at, as they sit in the letter (a gate is `N`, a leg is `N.M`), with the current one flagged; `--session <name>` → another session's. **No paths**: it resolves the pane, then `$TMUX`, then the live session-command directory through which it was invoked; viewer-safe. Exit 3 = no letter yet. |
| `write_tegami` | write-letter | `write_tegami --help` gives concise task-oriented usage without requiring a live session. One field, one call: `--objective <text>` · `--phase <title>` and `--gate <text>` append a rung · `--rung N <title>` retitles one · `--leg N <title>` appends a leg, `--leg N.M <title>` retitles one · `--status N[.M] PLANNED\|ACTIVE\|DONE`, with `--done` and `--active` as shorthand · `--drop N[.M]` · `--repo <repo>:<branch>` and `--unrepo` for the checkout rows · `--doc <path>` and `--undoc` for the doc list · `--on_tangent` / `--on_track` for the ladder state. Verbs combine in one call and apply in order; each runs through the same validator as a whole-block save, so `at`, `docs` and `teams` are carried through. `write_tegami < block.json` still replaces the authored fields wholesale (machinery-owned keys are reported and ignored). The separate `write_tegami --session <name> --at <position\|none>` form moves only another session's position marker. Control remains visible and does not restrict any of these. |
| `tejun-desk` | desk-open, desk-status, desk-sync, hand-in, desk-close | **Get, assign, update, hand in, close, and inspect managed worktrees.** `open <repo[:branch]> [--source dev|team]` defaults to current local `dev`; `team` explicitly starts from or adopts the Team's current local review line. Both resolve once and report/store the exact source SHA without changing the hand-in line. `assign <repo[:branch]> --session s --team t [--source dev|team]` gives the lead the same source choice for a named session. `sync <repo[:branch]>` merges current local `dev`; an empty update succeeds, and status gives both `dev` and line distance with an informational notice at 20 behind. `hand-in [<repo[:branch]>] [--assignment]` constructs an isolated candidate from current `dev`, accepted team delta, then desk delta; `ACCEPTED` reports the receipt and the called desk's excluded unsaved/untracked files and level. Conflicts and stale CAS attempts keep the desk and record evidence; handled exits clean their own candidate scratch. `close [<repo[:branch]>]` removes only a clean desk already contained in its line and refuses while a live session is inside it; `close … --with-session` validates the named desk, then uses the coordinated transaction to close every safe assigned desk before ending the Agent. Safe UI Delete, external delete, and harakiri use that same transaction; Archive leaves desk custody unchanged. `handoff` transfers owners; exact-confirmed discard records a receipt before deletion. `status [<repo[:branch]>]` reports lifecycle facts read-only. Exit 0 done · 2 bad arguments · 3 no matching desk/session · 4 not accepted · 5 stuck. |

Rules for adding tools:
- Add the executable, its catalog row, and the capability document that conditionally
  selects and teaches it.
- Tools report stored preferences and operational warnings without treating them as
  access-control decisions.
- Small, zero-dependency bash; concise outcomes and meaningful exit codes.
